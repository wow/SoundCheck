# sc-io

The file layer: decoding through symphonia (with encoder delay applied for MP3/AAC), the exact WAV/RF64/AIFF/AIFF-C reader `iff` (chunk table with header offsets, payload ranges, pad bytes and trailing bytes; `ds64` sizes; `fmt `/`COMM`+`SSND` format; streaming PCM in 4096-frame blocks, integers at their valid bit depth with non-zero padding bits counted, floats bit-exact; chunks past a stale container size are walked and marked; a trailing ID3v1 tag is a hard end; odd chunks without their pad byte are detected by following the chain of headers), the IFF render `render::apply_iff` (WAV/RF64 -> RIFF/WAVE, AIFF/AIFF-C -> FORM/AIFF; plain-PCM `fmt ` and 18-byte `COMM`; audio through `sc_dsp::Requantiser` at 16 or 24 bits with a BLAKE3 tee hash of the written PCM; a head cut snapped back up to 1 ms to the quietest frame (never later) and faded in over 2 ms with `sc_dsp::FadeIn` (`render::head`; `RenderReport` gives the cut made and the one requested), `cue `/`smpl`/`MARK` positions shifted by the cut made, PCM `fact` and `bext` TimeReference/loudness patched, `ds64`/`FVER`/float `fact` dropped, every other chunk and the trailing bytes carried byte for byte with their pad byte; refusals for more than two channels, rates other than 44.1/48 kHz, outputs past 4 GiB, peaks at full scale after gain, data in padding bits, a trim that starts inside a sampler loop, more than 16 MiB of chunks to rewrite, an AIFF past 2 GiB (signed `ckSize`); streamed in 4096-frame blocks, output created new and removed on any error or cancellation; read errors name the input, write errors the output), the ID3 editor `id3` (ID3v2.3/2.4 per id3.org: `parse_tag` indexes header, extended header and frames by byte range without decoding bodies except `TXXX` descriptions in encodings 0-3; `edit_tag` replaces frames whose label SoundCheck writes (`TBPM`, `TXXX:<name>` case-insensitive) in place and appends the rest once, keeps every other frame's bytes, version, revision and flags, reuses padding before growing the tag with 1 KiB of fresh padding, updates a v2.3 extended header's padding size and a v2.4 footer; ISO-8859-1 for ASCII text, else UTF-16 (v2.3) or UTF-8 (v2.4); tags up to 16 MiB; a tag with two copies in one file, tag-level unsynchronisation, undefined flags, an extended-header CRC or restrictions, another version, a broken structure (including a footer that does not repeat the header, and a v2.4 tag whose last binary frame also reads consistently with a plain 32-bit size, as old iTunes versions wrote them), or, for `TXXX` edits, a `TXXX` frame whose description cannot be read (compressed, encrypted, unknown encoding) is carried unchanged and reported as `NotEditable`; UTF-16 descriptions without a byte-order mark match in either byte order; `render::apply_iff` uses it for `RenderRequest.tag_edits` and never creates a tag in a file without one), the FLAC layer `flac` (RFC 9639: `read_layout` lists leading ID3v2 tags, every metadata block by byte range and an ID3v1/APEv2 tag after the frames; `FlacPcm` decodes frames exactly with flac-codec, fed only `fLaC` + STREAMINFO + frames, CRCs, count and MD5 checked; `FrameEncoder` encodes 4096-sample frames with flac-codec in frames-only mode, refusing out-of-range samples and frames larger than verbatim, and computes the STREAMINFO MD5 (md-5) and a BLAKE3 tee hash; `vorbis` re-emits a comment with the vendor and every field byte for byte, edits in place (case-insensitive names) or appended; `seektable` rebuilds a table with the source's point count; `cuesheet` shifts tracks and index points by a head trim (the lead-out is the last track) and refuses a trim that would break a CD-DA sheet; `decode_frames` re-decodes written frames with symphonia), the FLAC render `render::apply_flac` (same audio path and refusals as the IFF render; STREAMINFO, SEEKTABLE and PADDING rebuilt, the Vorbis comment edited, CUESHEET patched, every other block and the tags around the stream carried byte for byte; verified by a full symphonia decode against the encoder's BLAKE3 before it returns, output removed on any failure or panic; a source with frames past its declared total is refused; after a gain, stale `REPLAYGAIN_*`/`R128_*` fields (ID3 `TXXX:REPLAYGAIN_*`/`RVA2` for WAV/AIFF) are listed in `RenderReport::stale_loudness_tags`), the write transaction `txn` (`apply_in_place`, `apply_to_folder`, `recover` -> `RecoveryReport` with recovered and pending transactions, `undo`, `is_under_backup_root` for library scanners; paths resolved to their on-disk names (F_GETPATH); preflight refusals, all before anything is created, for paths in the backup root, rekordbox USB exports (`PIONEER/` at the volume root), symlinks, Finder-locked files, files of other users, hard links, ACLs (exacl on macOS, the POSIX ACL attribute on Linux), read-only files or folders and too little free space (output bound or backup + 64 MiB); a per-target lock for the whole transaction (polled, cancellable; a file changed while waiting is refused, never rendered twice) and a file identity (device, inode, length, mtime, ctime) checked before and after the backup copy and before the rename; the render into a hidden temp file in the same folder, synced with `F_FULLFSYNC` falling back to `fsync`, then verified from disk (WAV/AIFF header + audio BLAKE3, FLAC full decode); a backup made by the system copy (APFS clone or copyfile: whole resource fork and every attribute), synced, hashed by reading it back, under `<backup root>/<local yyyy-mm-dd>/<volume name>/<path relative to the volume>`, never overwritten, its name journaled before the rename; WAV/AIFF verification also compares every carried chunk and the trailing bytes with the source; no-replace renames fall back to an exclusive placeholder on exFAT/FAT; the atomic rename and folder sync; extended attributes (read at full size and read back; not `com.apple.provenance`, which the system sets on every new file and ignores writes to), group, creation date, mtime and mode restored; the `<file>.soundcheck.json` sidecar (schema 2, fixed key order; an export's `export` record of its settings, plans, exported grid and source measurements, journaled with the render so recovery writes the same sidecar; `sidecar::read` reads schemas 1 and 2) written atomically; for an export (`TxnOptions::export`) the render must have the planned frame count and cut, and with `TxnOptions::expect_original_blake3` the original must still hash to what was planned (else `FileChanged`), both before anything is written over; once the file is renamed into place the call succeeds, a journal line that cannot be written becoming a note for recovery to complete (when every line after the rename fails and the same file is changed again before that recovery, it records the first change as rolled back and keeps its backup, with a note); `journal.jsonl` with one synced line per state and a lock file per running transaction; recovery rolls back anything interrupted before the rename and completes anything after it, leaves unreachable or uncleanable transactions pending, and those whose file a newer change holds (its per-file lock), until `forget` ends one as `forgotten` (generated-shape ids only, looked up before any lock; nothing deleted); lock files are named only from checked ids or hashes; `resolve_file`, `resolve_backup_root`/`is_in_resolved_backup_root` and `tag_family` serve callers that check inputs and scan folders (and those whose target folder is not the journaled one: volume UUID from `diskutil` on macOS, cached 10 s, `startup` for the startup disk, statfs fsid on Linux, plus the folder's inode and birth time), and never deletes a backup unless the original is verified in place; undo puts the newest backup back through temp + verify + rename after checking the file is still SoundCheck's output; the volume name rule is in `txn/volume.rs`), the analysis cache (`cache`, keyed by the file's inode and status change time (not its device, which changes with the mount order), size, modification time, settings and version, so a file rewritten at the same length and time never serves the old record; `Cache::remove` drops a file's entry, which the engine does before and after every change), saved grid edits (`edits`, one per path and audio identity, so an edit of an exported file and the original's live side by side; files named by the path alone still read), and, as they land, the MP3-global-gain writer and the rekordbox XML and CSV writers.
Invariants: readers never modify files; writers carry every unknown chunk, frame and block verbatim; a write is atomic or it did not happen.

Tests: `tests/matrix.rs` is the file-layer fixture matrix. It builds 39 small synthetic WAV/RF64/AIFF/AIFF-C/FLAC files in code (fixed seeds) and lists every chunk, ID3 frame, FLAC block, Vorbis field and leading/trailing tag with its SHA-256 and expected fate: carried, patched (positions shifted by a head trim, `bext` loudness), replaced or dropped. Fifteen of them (`tests/matrix/cases_real.rs`) reproduce the chunk layouts and trailing-byte faults seen in DJ libraries exported by common taggers and DAWs: AIFF with `COMT` before `COMM` or after `SSND`, `NAME`/`ANNO`/`(c) ` in front of `COMM`, a 24-bit `CHAN`/`MARK`/`COMT`/`APPL` file, ID3v2.2/2.3/2.4 in the last `ID3 ` chunk, two zero bytes inside or after the `FORM`, one stray byte inside it, an odd last chunk without its pad byte, its zero pad byte written but left out of the `FORM` size (alone and followed by one more zero); WAV with `acid`, the Pro Tools set (`minf`, `elm1`, `regn`, `umid`, `DGDA`) and `cue `/`bext`/a second `LIST` after `data` at 48 kHz, two stray bytes inside the RIFF, an odd last chunk without its pad byte, and an `id3 ` chunk past a stale RIFF size. Bytes after the last chunk are carried after the output's container end (also where the source's container size counted them), a missing pad byte is restored as 0, chunks past a stale size are carried inside the output's container, and the output's container ends exactly at its last chunk. An independent reader checks them against `tests/fixtures/golden/file-layer-matrix.json` (`UPDATE_GOLDEN=1` rewrites it), and a reference writer proves the output checks accept a correct result and reject each injected mistake. The IFF writer tests run the matrix grid (0/-3.2/+2.1 dB x no trim/441 samples x loudness; a requested trim is checked against the cut a correct writer makes, snapped back to the quietest frame within 1 ms and faded in over 2 ms, worked out independently in `tests/matrix/expect.rs` and pinned for six fixtures in `literals.rs`) and the bit-depth rows through `render::apply_iff` in every `cargo test`, and the manifest's `outputs` section pins the SHA-256 of every IFF output (or `refused:<error kind>`, and the tests assert that kind); the ID3-edit test runs every IFF fixture with `TBPM`, `TXXX:BPM`, ReplayGain and `SOUNDCHECK` edits (its outputs for the tagged fixtures are pinned in the manifest too); the FLAC writer test runs every FLAC fixture over the grid with Vorbis edits and over the bit-depth rows through `render::apply_flac` (STREAMINFO fields, frame sizes, MD5 of the decoded output, seek points on frame starts, PADDING zero, every carried block and field byte-identical) and its outputs are pinned in the manifest; `flac_outputs_pass_flac_t` runs the reference `flac -t` on the outputs of unwrapped fixtures with `SC_FLAC_TOOLS=1`, and `tests/flac_tools.rs` (same switch, on in CI) renders sources encoded by the `flac` tool (block sizes 1152/2048/4608, a last frame under 16 samples, wasted bits, 8/16/24-bit, mono and stereo) at 0 and -3.2 dB and checks them with `flac -t -w`. `src/id3` has unit tests per module and a proptest over random frame lists and padding sizes (every other frame byte-identical and in order, the edited tag re-parses, a second identical edit changes nothing). `tests/matrix/walker.rs` checks that `iff` lists the same chunks as the independent parser and reads the generated samples on every IFF fixture; `tests/iff_fuzz.rs` runs proptest (256 cases each, `PROPTEST_CASES` for more) on random chunk soups and on random, truncated and mutated files through a reader that fails on any access past the end; `benches/iff.rs` measures walk + PCM on a 6-minute 24-bit stereo WAV, `benches/apply.rs` a -3.2 dB render of the same file from disk to disk, `benches/flac.rs` a -3.2 dB render of a 6-minute 24-bit stereo FLAC including the verifying decode, `benches/txn.rs` the whole in-place transaction (render, verify, backup, rename, metadata, sidecar, journal) on the same WAV and FLAC. `tests/txn.rs` runs the transaction end to end in temp folders (WAV, AIFF and FLAC in place with backup, sidecar, Finder tag, mode, mtime and creation date kept, then undone; copy to a folder; every refusal leaving the file untouched and nothing behind, the rekordbox export and full disk simulated through `VolumeProvider`; cancel during the render; undo across two changes and of an edited file). `real_files_render_without_loss` in `tests/matrix/real.rs` (opt-in `SC_REAL_FIXTURES=<folder>`, skipped when unset) renders every WAV/AIFF/FLAC file directly in that folder (sub-folders and other files skipped; the folder is only read, outputs go to the system temp folder and are removed) through `txn::apply_to_folder` with -1 dB and a BPM tag edit, checks each output with the matrix's independent reader and rules (block order, every carried chunk, frame, block and the trailing bytes byte-identical, the tag edit, DJ-safe headers, frame count, format and PCM within the matrix tolerances), then changes a copy in place and undoes it (same output bytes, byte-identical restore, no sidecar left); files the renderer refuses (`WouldClip`, `NotDjSafe`, ...) are reported, not failed; one line per file with `-- --nocapture` (`cargo test -p sc-io --test matrix real_files -- --nocapture`). `tests/disk_images.rs` (feature `crash-test`, opt-in `SC_DISK_IMAGES=1` on macOS) repeats copy, in-place change and undo on 200 MB exFAT and FAT32 images made with `hdiutil` (and a crash at the exFAT placeholder). `tests/crash.rs` is the crash matrix (feature `crash-test`, test-only, never in a shipped build): for every journaled state and the points between them (inside the render, the backup copy, before the backup's rename, between the rename and its line), for in-place changes of a WAV and a FLAC, copies to a folder and undos, it runs the `txn_apply` program (`examples/txn_apply.rs`, a bin target so Cargo builds it for the test) with `SC_TEST_CRASH_AFTER_STEP`, checks the abort, then `recover`: the original or the verified output at the path, no temp or lock file, backup present exactly when the rename happened, recovery idempotent, undo back to the original. Known decoder quirks the writers must handle (`iff` reads RF64 itself): symphonia 0.6.1 does not read RF64 and drops the last FLAC frame when an ID3v1 tag follows it; hound 3.5 ignores RIFF pad bytes; lofty 0.25 misreads RF64.
